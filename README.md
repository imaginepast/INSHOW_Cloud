# INSHOW Cloud for Home Assistant

INSHOW(인쇼) IoT 앱의 클라우드를 경유해 **75DF / T01 온도조절기**를 Home Assistant에서 쓰는 커스텀 통합입니다.

> ⚠️ 비공식 통합이며 제조사와 무관합니다. 인쇼 서버의 공개 API가 아니라 웹 앱이 쓰는 통신을 분석해서 만들었기 때문에, 제조사가 서버를 바꾸면 동작하지 않을 수 있습니다. 문제가 생기면 아래 [동작 확인](#동작-확인)을 먼저 해 보세요.

## 기능

계정에서 찾은 온도조절기마다 다음 엔티티가 만들어집니다.

| 엔티티 | 설명 |
|---|---|
| `climate` | 현재 온도, 설정 온도(9–35 °C, 0.5 °C 단위) 변경, 난방 중/대기 표시, 외출 모드 전환 |
| `sensor` | 실내 온도, 목표 온도, 운전 상태(외출 / 대기 중 / 난방 중) |
| `binary_sensor` | 난방 가동(릴레이) 상태 |

### 외출 모드

이 온도조절기에는 전원 끄기가 없습니다. 항상 켜져 있고, 기기의 전원 버튼을 누르면 **외출 모드**가 됩니다. 그래서 HA에서는 다음과 같이 표시됩니다.

| HA의 HVAC 모드 | 기기 상태 |
|---|---|
| `heat` (난방) | 일반 난방 (외출 해제) |
| `off` (끔) | **외출 모드** (전원 끄기가 아닙니다) |

- 외출 중에는 기기와 마찬가지로 설정 온도를 바꿀 수 없습니다. 목표 온도 센서는 계속 값을 보여줍니다.
- 통합이 시작될 때 컨트롤러가 **이미 외출 중이었다면 설정 온도를 알 수 없습니다.** 서버가 알려 주는 값이 외출을 해제할 때 기기가 복원하는 값과 다를 수 있어서, 틀린 값을 보여주는 대신 `알 수 없음`으로 표시합니다. 외출을 해제한 뒤 설정 온도를 한 번 지정하면 이후에는 정상적으로 표시됩니다.
- 자동화에서 `climate.set_hvac_mode`(`heat` / `off`)로 전환하세요. `climate.turn_on` / `climate.turn_off` 서비스는 지원하지 않습니다.
- 음성 비서나 자동화에서 "난방 끄기"를 하면 **외출 모드**로 바뀐다는 점에 주의하세요.

지원하지 않는 것: 냉방(에어컨) 모드, 예약/패턴 설정, 가상 기기.

## 요구 사항

- Home Assistant **2024.11 이상**
- 인쇼 IoT 앱에 이미 온도조절기가 등록된 계정 (이메일 로그인)
- 로컬(LAN) 방식이 아닙니다. HA가 인터넷으로 인쇼 클라우드에 접속합니다.

## 설치 (HACS)

1. HACS → 오른쪽 위 메뉴 → **사용자 지정 저장소**
2. 이 저장소 URL을 넣고 유형은 **Integration** 선택
3. **INSHOW Cloud**를 설치하고 Home Assistant를 재시작
4. 설정 → 기기 및 서비스 → **통합 추가** → *INSHOW Cloud* → 인쇼 계정 이메일/비밀번호 입력

수동 설치: `custom_components/inshow_cloud` 폴더를 HA의 `config/custom_components/` 에 복사하고 재시작합니다.

## 동작 확인

설정 후 **설정 → 시스템 → 로그**에서 다음을 확인하세요.

| 로그 / 증상 | 의미 |
|---|---|
| `INSHOW MQTT connected (N controller(s))` | 정상. 로그인과 MQTT 연결 모두 성공 |
| 통합이 "재시도 중" | 서버/네트워크 일시 오류. 자동으로 다시 시도합니다 |
| "…연결을 거부했습니다 (Not authorized)" | **인쇼 브로커가 외부 클라이언트를 거부**한 경우. 이 통합으로는 해결할 수 없습니다 → 이슈로 알려 주세요 |
| `INSHOW sign-in was rejected (코드), attempt 1 of 3` | 서버가 로그인을 거부했습니다. 서버의 일시적인 문제일 수 있어 자동으로 최대 3번 다시 시도합니다. 이 줄의 **코드**를 이슈로 알려 주세요 |
| 재인증 알림 | 로그인이 3번 연속 거부됐습니다. 비밀번호가 바뀌었다면 알림에서 새 비밀번호를 입력하세요 |
| 설정 온도나 외출 모드를 바꿨다가 10초 뒤 되돌아감 | 컨트롤러가 변경을 확인해 주지 않았습니다 (경고 로그 기록). 보통 확인은 1초 안에 옵니다. 기기가 꺼져 있거나 인쇼 서버 연결이 불안정한지 확인하세요 |
| 엔티티가 `사용 불가` | MQTT 연결이 끊긴 상태. 연결이 복구되면 자동으로 돌아옵니다 |

## 문제 보고용 진단 로그

동작이 이상할 때 원인을 찾으려면 통합이 주고받는 메시지의 모양을 봐야 합니다. 디버그 로그를 켜면 `INSHOW rx`(받은 메시지)와 `INSHOW tx`(보낸 명령) 줄이 남습니다.

```yaml
logger:
  default: warning
  logs:
    custom_components.inshow_cloud: debug
```

1. 위 설정으로 로그 수준을 바꿉니다. 통합 화면의 ⋮ → **디버그 로깅 사용**으로도 켤 수 있습니다.
2. 문제가 생기는 동작을 한 번 해 봅니다. (예: 기기에서 외출 → 난방 전환, HA에서 설정 온도 변경)
3. 설정 → 시스템 → 로그에서 `INSHOW rx` / `INSHOW tx` 줄만 복사해 이슈로 알려 주세요.

개인정보는 로그에 남지 않도록 처리했습니다. 컨트롤러 ID는 `<ctrl1>`, `<ctrl2>`…로 바뀌고, 값은 숫자·참/거짓과 `ON`/`OFF`/`heat` 같은 정해진 몇몇 단어만 보입니다. 사용자 이름을 포함한 나머지 문자열은 `<str:길이>`로, ID 필드(`_id`, `deviceId` 등)의 값은 `<id>`로 가려집니다. 그래도 올리기 전에 한 번 훑어보세요.

## 개인정보와 보안

- 이메일과 비밀번호는 HA의 설정 저장소(`.storage/core.config_entries`)에 **평문**으로 저장됩니다. 클라우드 통합에서 흔한 방식이지만, HA 백업이나 `.storage` 폴더를 공유하면 같이 노출됩니다. 가능하면 HA 전용 계정을 쓰세요.
- 진단 파일(설정 → 기기 및 서비스 → INSHOW Cloud → 진단 다운로드)에서는 이메일, 비밀번호, 방 이름이 가려집니다.
- **이슈를 올릴 때 HAR 파일, 토큰, 비밀번호, 기기 시리얼(controller ID)이 들어 있는 로그를 첨부하지 마세요.** 로그 전체에는 다른 통합의 정보(기기 이름 등)가 섞일 수 있으니 `INSHOW`가 들어간 줄만 복사하세요. 이 저장소의 `.gitignore`는 `*.har`를 제외하도록 되어 있습니다.

## 알려진 한계

- 인쇼 서버가 외부 MQTT 클라이언트를 허용하는지는 계정/기기마다 다를 수 있습니다.
- 외출 명령은 웹 앱에서 확인한 `AWAYMODESET`을 사용합니다. `1`은 외출, `0`은 외출 해제이며 앱 상태의 `onoff` 값은 반대로 매핑됩니다(`onoff == 0`이면 외출).
- 기기에서 직접 바꾼 외출/난방은 기기가 보내는 `AWAYMODESET` 보고(`AwayModeSet`: `1` = 외출, `0` = 해제)로 HA에 반영됩니다. HA에서 외출/난방이나 설정 온도를 바꾸면 화면에 바로 표시되고, 기기가 10초 안에 확인해 주지 않으면 이전 상태로 되돌립니다.
- 계정에 기기를 새로 추가했다면 통합을 **다시 불러오기** 해야 인식됩니다.
- 기기 상태는 시작할 때 인쇼 서버에서 한 번 받아 오고, 이후에는 MQTT로 오는 변경 알림으로만 갱신됩니다(폴링 없음). MQTT 연결이 끊겼다가 복구되면 그 사이 기기에서 바꾼 상태는 다음 변경이 있거나 통합을 다시 불러올 때까지 반영되지 않을 수 있습니다.
